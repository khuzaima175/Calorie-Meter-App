# CalorieSnap Pro audit — 2 October 2026

The active application is the React Native/Expo app in `src`, with custom tab navigation, three Zustand stores, SQLite on native platforms, and localStorage/IndexedDB on web. The root Python/Qt files are a separate legacy application; this repair pass targets the active Expo application.

## Continuation pass

The second pass fixed additional interaction and calculation defects:

- Walking inputs no longer clamp zero/invalid steps into a phantom one-minute walk. Calculations preserve the exact duration derived from whole step counts, and unit switches retain the current quantity.
- The walking shortcuts now add minutes/steps as their labels promise instead of replacing the existing amount.
- Preset calorie estimates update when weight changes and scale intensity relative to the preset's baseline.
- Exercise AI results are invalidated after description, weight, or modal-session changes. Pending forms lock their selectors as well as text fields.
- Manual meal saves capture the selected diary date before AI estimation. Leaving the screen cancels a pending estimate before persistence and prevents a late navigation after an already-started write.
- Valid zero-calorie AI estimates can be saved. Quick-add results/errors from a previous modal session cannot overwrite the new session, and synchronous save locks prevent same-frame duplicate writes.
- Decimal and litre water portions are parsed without concatenating digits. Analysis fields and cancellation controls are locked during saving.
- Camera barcode lookups require an explicit rescan after completion, preventing repeated failed lookups while a barcode remains in view. Camera mount failures show a manual-entry fallback, and rejected callbacks are handled.
- Barcode nutrition uses a consistent per-serving or per-100g basis when the serving weight is unknown. Unscalable missing macros retain the existing zero fallback rather than mixing incompatible quantities.

## Verification

- Production-code regressions run through `tests/load-production.cjs`; only device/platform adapters are mocked.
- All 48 tests pass, including nine production-handler/calculation regressions for the continuation pass and three added during full uncommitted verification. The form harness drives state, effects, unmounts, deferred AI replies, and repeated taps without a camera or paid API call.
- Persistence tests use an actual in-memory SQLite engine and force an import write failure to verify rollback. Web tests force storage quota failures, restart cleared storage, and round-trip backups.
- Store/service tests cover out-of-order reads, writes during navigation, API-key preservation, failed saves, chat concurrency/clearing, AI output normalization, and barcode units.
- Browser accessibility inspection confirmed the dashboard, distinct meal actions, settings inputs, and quick meal validation. Entering negative calories displayed an error without saving a meal.
- Expo production exports succeeded for web, Android, and iOS. These are JavaScript/Hermes bundles, not installed APK/IPA device tests.
- Browser screenshot capture timed out, so pixel-level visual QA is unverified.

## Remaining verification limits

The legacy README claims broad feature/a11y coverage and contains older test totals. This audit records what was actually verified, without treating those claims as evidence.

## Full uncommitted verification

Reviewed the combined working-tree changes from both audit passes: 32 modified tracked files and 11 new files. No staged changes were present, and no commit was created.

Verification uncovered and corrected three additional gaps: water logging ignored its explicit date argument; a synchronous browser storage error could leave a rejected initialization promise cached and break Retry Loading; browser startup validated log records but did not validate the merged saved profile/goals. Added regressions for explicit-date hydration, initialization retry, and recovery from an invalid saved profile without overwriting stored data.

Final checks: 48/48 tests pass; all 44 source modules parse with no duplicate JSX attributes or unexpected unbound identifier references; `git diff --check` passes; fresh web, Android, and iOS production exports succeed in `.expo/verified-uncommitted`. The earlier device and pixel-verification limits still apply.
